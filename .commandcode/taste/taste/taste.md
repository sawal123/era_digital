# Taste
- Communicates in Indonesian (Bahasa Indonesia) and expects the conversation to be conducted in Indonesian. Confidence: 0.9
- The business/store operates in WIB (UTC+7); any date/time handling in the app (POS sale dates, reports, daily filters) must be consistent with WIB, not UTC. Confidence: 0.7
- When a feature depends on an external API, verify the API directly (e.g. curl the endpoints) to pin down whether the root cause is the external service or the app code, rather than assuming the app is at fault. Confidence: 0.6
- Corrective data migrations must select affected rows by data conditions (e.g. exact timestamp deltas against related rows), never by arbitrary ranges like ID thresholds, and must be defensive: driver-guarded, idempotent, and a no-op when no matching data exists. Confidence: 0.9
- Never edit or roll back a migration that has already run in production; ship a new corrective migration instead. Confidence: 0.9
- Keeps work strictly scoped to the stated bug — no refactoring of unrelated subsystems, schema, UI, or financial logic, and no manual queries against production. Confidence: 0.8
- Runs the specific/affected tests first, then the wider relevant test suite. Confidence: 0.7
- Prefers deterministic tests for date/time behavior using Carbon::setTestNow(). Confidence: 0.7
- Git workflow: pull latest main, create a feature branch, never merge to main directly, and never force push. Confidence: 0.8
- Prefers no step-by-step narration of the work process; final report should be a concise structured summary (branch, files changed, core fix, tests run with PASS/FAIL, status). Confidence: 0.8
- Treats backend/database timestamps as the single source of truth — data bugs must not be patched in the frontend, and the frontend must not re-convert timezones already handled by the backend. Confidence: 0.7
